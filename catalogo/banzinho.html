material grátis

Três dicas que valem por si

É o essencial do método, sem enrolação. Dá para montar um agente muito melhor que a média só com isto.

  • Regra que só vive no prompt morre no prompt. Toda regra importante precisa de um verificador: um teste que quebra a build quando alguém apaga a regra. O prompt convence; o verificador garante.
  • Estado sobrevive à sessão ou não aconteceu. Tudo que importa no fim do turno vai para o disco (tarefa, decisão, falha, próxima etapa) — memória de chat não é memória.
  • Recusa raramente existe. Falta de ferramenta vira contorno, ambiguidade de técnica vira decisão documentada, e a irreversibilidade que vale uma linha de consequência roda igual.

Config de partida (exemplo)

# agents.config.example — ponto de partida, não é a config real do Banzinho
indice:
  porta_de_entrada: AGENTS.md          # a regra global carrega aqui
precedencia: [pedido, constitution, subsistema, estado]
turno:
  fechar_so_com: objetivo_verificado
  estado_persistente: task ledger          # tarefa/decisão/prova no disco, não no chat
verificadores:
  _so_vai_verde: sim                    # regra sem verificador não é regra
